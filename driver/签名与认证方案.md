### 驱动改进（本次针对你提的设备名匹配问题）

我逆向确认了参考驱动的真正机制：

```
ComDrv12x64.sys 的 sub_12a24:
  ZwOpenDirectoryObject("\Device")        ← 打开设备目录
  ObReferenceObjectByHandle(...)          ← 取得目录对象
  sub_127b0: 遍历目录对象散列表 + 递归子目录
             用 RtlCompareUnicodeString 匹配 "Serial" / "VSerial" 命名空间
```

**它是枚举设备目录，不是硬编码名字** —— 所以能覆盖所有端口。

我的驱动改成了等价做法：`ZwQueryDirectoryObject` 枚举 `\Device`，
按 16 类名称片段识别（Serial/USBSER/Prolific/Silabser/VSerial/VCP/FTDI/BthModem/cdc_acm/Ch341/MCT_U232 等），再动态附加。

> 注：参考驱动走的是**未文档化的目录对象散列遍历**（对 `OBJECT_DIRECTORY`
> 内部结构强依赖，换 Windows 版本可能失效）。我用的 `ZwQueryDirectoryObject`
> 是官方文档化 API，语义等价但更稳。

## 二、驱动签名与认证（三个层级）

### 层级 1：测试签名 —— 开发自用（当前方案）

```powershell
bcdedit /set testsigning on    # 管理员，需重启
```
- **成本**：0 元
- **范围**：只在本机有效，且必须重启 + 桌面右下角显示"测试模式"
- **适用**：你自己开发测试
- ✅ 已完成：驱动已用自签名证书签名

### 层级 2：EV 代码签名证书 —— 商业分发的基础

| 项 | 说明 |
|---|---|
| 证书类型 | **EV Code Signing Certificate** |
| 价格 | 约 **¥3,000-5,000/年** |
| 供应商 | DigiCert / Sectigo / GlobalSign / SSL.com |
| 交付方式 | **硬件令牌（USB Key）**，无法导出私钥 |
| 作用 | 让驱动通过 Windows 的"签名验证"（错误码 577 消失） |

**⚠️ 重要**：有了 EV 证书**还不能直接分发驱动**。Windows 10/11 x64
要求内核驱动必须通过 **Microsoft 的认证签名**（见层级 3），EV 证书只是
提交认证的前提。

### 层级 3：WHQL / Attestation 签名 —— 正式分发（必需）

微软提供两条路径，都要求先有 EV 证书：

| 路径 | 要求 | 适用 |
|---|---|---|
| **Attestation Signing** | 自测通过 + EV 证书 + 提交 .cab | 通用驱动（推荐） |
| **WHQL（HLK）** | 跑完整 HLK 测试套件（几十项） | 需要 Windows Update 分发的驱动 |

**流程**：
1. 购买 EV 证书，注册 **Microsoft Partner Center** 账号（免费）
2. 创建 .cab 包，用 EV 证书签名
3. 通过 Partner Center 提交（Attestation 或 HLK）
4. 微软审核通过后返回**微软签名的 .sys**，这个才能在用户机器上直接加载

**成本**：EV 证书 ¥3,000-5,000/年 + Partner Center 账号（免费）+ 审核时间 1-3 天

## 三、能否复用参考程序（CommMonitor）的驱动？

### 技术上：❌ 不可行

我检查了 `ComDrv12x64.sys` 的签名：

```
签名者: DigiCert EV Code Signing CA
        带 Microsoft 交叉签名（cross-certificate）
        Thawte Timestamping CA
```

原因：
1. **它是别人（CEIWEI）的签名**，我们无法获得对应私钥
2. 即使能提取文件，**微软的认证签名是绑定到具体文件哈希的** ——
   修改一个字节签名即失效
3. 分发他人驱动属于**侵犯著作权**，且 CEIWEI 有 EV 证书做法律保护

### 但可以"参考"：✅ 已做

我们做的是**逆向分析其机制**（合法）：
- 确认它是上层设备过滤驱动（`IoAttachDeviceToDeviceStack`）
- 确认它用目录枚举发现端口（`ZwOpenDirectoryObject`）
- 确认它用 `IoBuildAsynchronousFsdRequest` 旁路读取
- 提取了它的 IOCTL 编码方式

然后**自己实现**同样的功能 —— 这才是 craft-anything 的"clean room 复刻"。

### 折中方案：让用户自己装参考软件？

❌ 不推荐：
- 用户仍需购买 CEIWEI 的授权
- 我们的软件变成"寄生"在其驱动上，法律风险高
- CEIWEI 驱动接口未公开，逆向其 IOCTL 协议可能违反其 EULA

1. 开测试签名 + 重启
2. 加载我们自己的驱动
3. GUI 里点「启用驱动捕获」测试功能

### 阶段 2：功能验证后（自用）

如果想在**自己的多台机器**上用，仍可用测试签名：

### 阶段 3：商业分发（需要投入）

- **必须**买 EV 证书（¥3,000-5,000/年）
- **必须**通过微软 Attestation 认证
- 走完流程后，用户**双击安装包即可**，无需任何手动配置

### 阶段 4：如果不想投入证书成本

**替代方案**：把驱动改成"可选增强"：
- 默认使用**用户态方案**（已可用，但有"先附加后开端口"限制）
- 检测到用户已开测试签名/已装驱动时，自动启用驱动模式
- 文档说明"想要全自动监控，请按指引开启测试签名"

这样软件可以**免费分发**，高级功能由用户自行选择启用。
