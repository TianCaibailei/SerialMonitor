## 一、回答你的问题：挂接所有串口，但只监视指定端口？

### 参考程序的做法（已逆向确认）

**参考驱动挂接所有串口，记录所有数据，不做端口过滤。**

证据：记录写入函数 `sub_1250c` 的完整汇编里**没有任何端口判断**：

```
0x12539: cmp ebx, 0x2000f      ← 只检查长度上限（128KB）
0x12545: KeAcquireSpinLock     ← 直接加锁
0x1257f: lock add [0x20544],1  ← 序号递增
0x1258d: movdqu xmm0,[rdi]     ← 复制时间戳
0x125c2: repne scasw           ← 计算设备名长度
0x125db: call 0x12dc0          ← 复制设备名到记录 +0x1c
0x125fc: call 0x12dc0          ← 复制数据到记录 +0x40
```

它唯一的"区分"手段是在每条记录里带上**设备名**（固定 32 字节，位于 `+0x1c`），
由**用户态**按名字分拣到不同窗口。

### 我们当前的做法

**完全一致**：

| 项 | 参考驱动 | 我们 |
|---|---|---|
| 挂接范围 | 所有 `\Device\Serial*` / `\Device\VSerial*` | 同 |
| 驱动侧端口过滤 | 无 | 无 |
| 端口标识 | 记录里带设备名（32 字节） | 记录里带 `PortIndex` + 用户态查名字 |
| 用户态分拣 | 按名字分到不同窗口 | 按 `PortIndex` 分到不同通道 |

**结论：这是参考程序验证过的设计，是正确做法。** 理由：

1. 驱动侧不知道用户要监控哪个端口（用户随时可能改）
2. 挂接全部端口后，用户态可以随时切换监视目标，无需重新挂接
3. 记录中带端口标识即可，数据不会混淆

**唯一差异**：我们的记录用 `PortIndex`（4 字节索引）而非 32 字节设备名，用户态通过
`IOCTL_UM_GET_PORT_NAME` 查一次名字后缓存。功能等价，传输效率更高。

## 二、串口参数过滤：已实现

### 驱动侧（22,528 字节，编译通过）

#### 新增捕获的 8 个 IOCTL

| IOCTL | 值 | 记录内容 |
|---|---|---|
| `IOCTL_SERIAL_SET_BAUD_RATE` | 0x1B0004 | 波特率 |
| `IOCTL_SERIAL_GET_BAUD_RATE` | 0x1B0050 | 波特率 |
| `IOCTL_SERIAL_SET_LINE_CONTROL` | 0x1B000C | 数据位/停止位/校验 |
| `IOCTL_SERIAL_GET_LINE_CONTROL` | 0x1B0054 | 同上 |
| `IOCTL_SERIAL_SET_TIMEOUTS` | 0x1B001C | 5 个超时值 |
| `IOCTL_SERIAL_GET_TIMEOUTS` | 0x1B0058 | 同上 |
| `IOCTL_SERIAL_SET_HANDFLOW` | 0x1B0044 | 流控位 |
| `IOCTL_SERIAL_GET_HANDFLOW` | 0x1B0060 | 同上 |

#### 数据流

```
应用调用 SetCommState / 设置波特率
   ↓
IRP_MJ_DEVICE_CONTROL 到达我们的过滤设备
   ↓
UmIsSerialControlIoctl(code) 判断是否是串口参数 IOCTL
   ↓ 是
分配 UM_CTRL_CTX，安装 UmCtrlComplete 完成例程
   ↓
转发给真正的串口驱动（原样，不改任何值）
   ↓
串口驱动完成，状态 SUCCESS
   ↓
UmCtrlComplete 从缓冲区读出**实际生效的参数**
   ↓
UmQueueControlRecord 写入队列（Dir = UM_DIR_CTRL = 2）
   ↓
用户态读取，显示为"控制"行
```

**关键设计**（按你的要求）：

- ✅ **只显示不改写** —— 参数原样转发给串口驱动，不修改任何值
- ✅ **记录成功后的实际值** —— 完成例程里检查 `NT_SUCCESS(IoStatus)`，失败的 SET 不产生记录
- ✅ **混在表格里** —— 同一队列，用 `Dir = 2` 区分

#### 记录格式

```c
typedef struct _UM_CTRL_INFO {
    UINT32 IoctlCode;    // 哪个操作
    UINT32 BaudRate;     // 波特率
    UINT32 HandFlow;     // 流控
    UINT32 Timeouts[5];  // 5 个超时值
    UINT8  DataBits;     // 5-8
    UINT8  StopBits;     // 0=1, 1=1.5, 2=2
    UINT8  Parity;       // 0=无,1=奇,2=偶,3=标记,4=空格
    UINT8  Reserved;
} UM_CTRL_INFO;   // 36 字节
```

### GUI 侧（编译通过）

新增 `RecordKind::Control`，解析后生成可读摘要：

| IOCTL | 显示 |
|---|---|
| SET_BAUD_RATE | `设置波特率 9600` |

## 四、验证参数过滤是否生效

用串口助手打开 COM6，**修改波特率**（比如从 9600 改到 115200）。

GUI 表格里应该出现：

```
时间      通道  方向   长度  数据
15:40:01  COM6  控制   36    设置波特率 115200
15:40:05  COM6  控制   36    8N1
```

### 如果不显示控制行

可能原因：

1. **驱动是旧版**（21,896 字节）—— 检查文件大小必须是 22,528
2. **串口助手用的是 .NET SerialPort** —— 它在打开端口时设参数，此时可能还没挂接
   → 先启用驱动捕获，再打开串口助手
3. **参数是在 CreateFile 时设的** —— 某些库用 `CreateFile` 的 DCB 参数，不发 IOCTL
