# 驱动启动失败诊断与修复

> 2026-11-11 · 已找到根因并修复代码，需要重启一次清除卡住的服务

## 一、你的两个问题

### Q1：服务在服务管理器里能看到吗？

**内核驱动服务默认不在 `services.msc` 里显示**（那里只列 Win32 服务）。三个查看方式：

| 方式 | 命令/路径 | 说明 |
|---|---|---|
| 命令行（推荐） | `sc query UmSerialFilter` | 最直接，显示 STATE |
| 命令行 | `sc qc UmSerialFilter` | 显示 binPath 等配置 |
| 命令行 | `driverquery /v \| findstr UmSerial` | 列出所有驱动 |
| 设备管理器 | 查看 → 显示隐藏的设备 → **非即插即用驱动程序** | 图形界面里的位置 |

> 它是一个**内核驱动服务**（`SERVICE_TYPE = 1 KERNEL_DRIVER`），不是普通后台程序，
> 所以不会出现在服务管理器的常规列表里。

### Q2：为什么内核服务会启动失败？

因为**驱动的 `DriverEntry` 卡住了** —— 我代码里有两个真实 bug：

#### Bug 1：目录枚举死循环（主因）

```c
// 错误代码
status = ZwQueryDirectoryObject(dirHandle, buf, bufLen,
    TRUE /* RestartScan */, TRUE /* SingleEntry */, &context, &retLen);
```

`RestartScan=TRUE` 表示**每次都从头开始枚举**。配合 `SingleEntry=TRUE`（每次返回一条），
内核永远返回同一条记录 → **无限循环** → `DriverEntry` 永不返回 →
服务永远停在 `START_PENDING`。

**修复**：只在第一次调用时 `RestartScan=TRUE`，之后用 `context` 继续：

```c
(context == 0) ? TRUE : FALSE
```

#### Bug 2：在 DriverEntry 里附加设备（次因）

```c
UmAttachAllPorts();   // ← 在 DriverEntry 中调用
```

`DriverEntry` 执行时，I/O 管理器还在初始化启动设备栈。
此时调用 `IoGetDeviceObjectPointer` / `IoAttachDeviceToDeviceStack`
可能阻塞在尚未就绪的设备上。

**修复**：`DriverEntry` 只做初始化 + 注册热插拔通知；
设备附加改由用户态通过 `IOCTL_UM_ATTACH_PORTS` 触发（此时驱动已 RUNNING）。

#### 这解释了 1072 错误

`sc delete` 返回 1072（`ERROR_SERVICE_MARKED_FOR_DELETE`）是因为：
驱动卡在 `DriverEntry` 中，Windows 无法卸载它，服务标记为"待删除"但实际删不掉。
**只有重启能清除**。

## 二、为什么要重启

当前状态：

```
STATE : 2 START_PENDING   ← 驱动卡在加载中
```

`START_PENDING` 的驱动：
- 无法 `sc stop`（会报 1052 或挂起）
- 无法 `sc delete`（1072）
- 一直占用 `umserialfilter.sys` 文件（导致重新编译时报 LNK1104）

**重启是唯一解法。**

## 三、重启后的完整步骤

### 步骤 1：确认测试签名（关键！）

```powershell
bcdedit /enum {current} | Select-String testsigning
```

**如果输出为空（未开启）**，说明还需要开：

```powershell
# 管理员 PowerShell
bcdedit /set testsigning on
```
→ **再重启一次**

> 我检查到你的系统当前 `testsigning` 是空的。如果没有开启测试签名，
> 驱动即使修好了也会报 **577 签名验证失败**。

### 步骤 2：清理旧服务

```powershell
# 管理员 PowerShell
sc delete UmSerialFilter
```

重启后驱动已卸载，这条应当成功。

### 步骤 3：重新编译并签名驱动

```powershell
cd E:\Documents\MonitorAnything\MonitorAnything\driver
powershell -ExecutionPolicy Bypass -File build-driver.ps1 -Source umserialfilter\umserialfilter.c
```

然后签名：

```powershell
$signtool = 'C:\Program Files (x86)\Windows Kits\10\bin\10.0.19041.0\x64\signtool.exe'
$thumb = '89504FECC3504FB928B20D7034A82BF91F71423A'
& $signtool sign /s My /sha1 $thumb /fd SHA256 umserialfilter\umserialfilter.sys
```

### 步骤 4：安装并启动

```powershell
powershell -ExecutionPolicy Bypass -File setup-driver.ps1
```

## 四、如果再次卡住怎么办

升级后的 `setup-driver.ps1` 会**检测 START_PENDING 并给出明确提示**，
不会再让你在 1072 错误里困惑。

排查清单：
1. `sc query UmSerialFilter` 看 STATE
2. 如果是 `STOPPED` + `WIN32_EXIT_CODE 577` → 测试签名没生效（需重启）
3. 如果是 `START_PENDING` → DriverEntry 卡住（本次已修，若仍出现说明还有别的阻塞点）
4. 看事件查看器 → Windows 日志 → 系统，筛选来源 `Service Control Manager`

## 五、修复后的代码变更

| 变更 | 原因 |
|---|---|
| `ZwQueryDirectoryObject` 的 `RestartScan` 改为条件式 | 修复无限循环 |
| 移除 `DriverEntry` 中的 `UmAttachAllPorts()` 调用 | 避免初始化期阻塞 |
| 新增 `g_AttachLock` 自旋锁 | 热插拔回调与 IOCTL 并发访问保护 |
| 新增 `UmAlreadyAttached` 去重 | 防止同一设备被附加两次 |
| 新增 `UmRegisterAttached` 统一注册 | 索引分配原子化 |
| `UmAttachOne` 加索引校验 | 防越界 |
