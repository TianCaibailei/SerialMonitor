# 六项 GUI 问题修复说明

> 2026-11-11 · 基于实机测试反馈

---

## 问题 1：数据显示慢一拍

### 原因

`drain_driver()` 每帧从通道读取数据，但界面**每 60ms 才重绘一次**：

```rust
ctx.request_repaint_after(Duration::from_millis(60));
```

数据到达后被读进批次，但要等下一次重绘才显示。60ms 正好等于用户"发下一条消息"的间隔，所以看起来总是慢一拍。

### 修复

```rust
// 60ms → 16ms（约 60fps）
ctx.request_repaint_after(Duration::from_millis(16));
```

## 问题 2：时间显示 1970-01-01

### 原因

**驱动和 GUI 的时间基准不一致**：

| 侧 | 原来 | 说明 |
|---|---|---|
| 驱动 | `KeQuerySystemTime()` 原始值 | FILETIME：**1601-01-01 起**的 100ns 计数 |
| GUI | `fmt_time(secs, millis)` | 期望 **Unix 秒**（1970-01-01 起） |

GUI 里写的转换是：

```rust
let secs = rec.timestamp / 10_000_000 % 86_400;   // 取当日秒数
```

`FILETIME / 10^7` 得到的是"1601 年起的秒数"，取模 86400 后是个毫无意义的小数字，`fmt_time` 把它当 Unix 秒 → 显示 1970。

### 修复

**驱动侧**新增转换函数，直接输出 Unix 毫秒：

```c
static ULONGLONG UmNowUnixMillis(VOID)
{
    LARGE_INTEGER now;
    // 1601-01-01 到 1970-01-01 之间的 100ns 计数
    const ULONGLONG EPOCH_DIFF_TICKS = 116444736000000000ULL;

    KeQuerySystemTime(&now);
    if ((ULONGLONG)now.QuadPart <= EPOCH_DIFF_TICKS) {
        return 0;
    }
    return ((ULONGLONG)now.QuadPart - EPOCH_DIFF_TICKS) / 10000ULL;
}
```

**GUI 侧**简化为：

```rust
let secs = rec.timestamp / 1000;
let millis = (rec.timestamp % 1000) as u32;
```

## 问题 3：数据列文本被截断

### 原因

数据列渲染时有一行：

```rust
let mut t = escape_text(&r.data, s.ascii_escape);
t.truncate(s.string_len.max(4));   // ← string_len 默认 16
ui.label(t);
```

`string_len` 是原程序的一个显示偏好（默认 16），
所以 `"Welcome to UartAssist 23"`（24 字节）被砍成 `"Welcome to UartA"`（16 字节）。

### 修复

删除截断。列宽不够时 egui 会自动视觉裁切，但**数据本身完整保留**（可选中复制、可查看详情）。

```rust
let t = escape_text(&r.data, s.ascii_escape);
ui.label(t);   // 不再 truncate
```

## 问题 4：监视所有串口，无法只监视指定端口

### 现状说明

驱动**故意挂接所有串口**并上报全部数据 —— 这与参考驱动一致（已逆向确认 `sub_1250c` 里没有任何端口判断）。
好处是用户切换端口时无需重新挂接。

**过滤应该在 GUI 侧做**，之前没做。

### 修复

新增端口白名单：

```rust
/// 用户实际要监视的端口（短名，如 "VSerial8_2"）。
/// 空集合 = 不限制。
pub drv_watch: HashSet<String>,
```

启用捕获时，从当前会话的通道名构建：

```rust
self.drv_watch.clear();
if let Some(s) = self.sessions.get(self.active) {
    for c in &s.channels {
        if c.kind == ChanKind::HookSerial && !c.name.trim().is_empty() {
            self.drv_watch.insert(c.name.to_string());
        }
    }
}
```

`drain_driver()` 里丢弃不在集合中的记录：

```rust
if !self.drv_watch.is_empty() {
    let watched = rec_name.as_ref().map_or(false, |n| self.drv_watch.contains(n));
    if !watched { continue; }
}
```

**效果**：会话里选了 COM6，就只显示 COM6 的数据，其他端口静默丢弃。

## 问题 5：功能列显示 "00 Unknown"

### 原因

会话协议默认是 **Modbus RTU**（状态栏可见），所以串口原始字节被送进了 Modbus 解析器：

```
"Welcome to UartAssist 23" 的前几字节 → 被当成 MBAP 帧头
→ 解析出 function = 0x00 → fc_name(0) = "Unknown"
```

实际上是**纯串口数据，不是 Modbus 帧**。

### 修复

新增行来源标记：

```rust
pub enum RowOrigin {
    Channel,   // 注入 hook 或真实协议通道
    Driver,    // 内核驱动捕获的原始串口字节
}
```

功能列按来源显示：

```rust
if let Some(ci) = &r.control {
    ui.label(ci.summary());                    // 控制记录：显示具体操作
} else if let Some(p) = &r.parsed {
    ui.label(format!("{:02X} {}", p.function, fc_name(p.function)));  // 真 Modbus
} else if r.origin == RowOrigin::Driver {
    ui.label(if r.dir_tx { "串口写" } else { "串口读" });   // 驱动捕获
} else {
    ui.label(r.kind.name());
}
```

**效果**：
- 驱动捕获的串口数据 → 显示 `串口读` / `串口写`
- 串口参数变更 → 显示 `设置波特率 9600` / `8N1`
- 真正的 Modbus 帧（来自注入 hook）→ 仍显示 `01 请求` 之类

另外新增 `Session::ingest_driver()`，驱动数据**跳过协议解析和行合并**，直接成行。

## 问题 6：数据列按读写着色

### 修复

数据列（Hex 与文本两列）都改为按方向着色：

```rust
let color = if r.control.is_some() {
    C_REQ                     // 控制记录：另一种颜色
} else if r.dir_tx {
    C_TX                      // 写：与"写"字同色
} else {
    C_RX                      // 读：与"读"字同色
};
```

这样 Hex 数据、文本数据、方向文字**三处颜色一致**，扫一眼就能区分收发。

## 仍待确认

1. **控制记录的方向列** 目前显示 `读`（因为 `dir_tx = false`）。是否需要改成 `控制`？
   改动很小，但涉及会话过滤逻辑（`全部/读/写` 筛选），需要你确认。
2. **端口过滤的匹配方式** 用的是短设备名（`VSerial8_2`）。如果你的界面里通道名是 `COM6` 这种形式，
   匹配会失败 —— 需要确认当前通道名显示的是什么。
