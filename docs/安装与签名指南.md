# 驱动安装与签名指南

本项目的内核过滤驱动 `umserialfilter.sys` 需要在**测试签名环境**下才能加载。
本文给出从零开始的完整流程：准备测试环境 → 生成证书 → 签名 → 安装 → 验证 → 卸载。

> **重要前提**：以下流程仅适用于开发与自用。对外分发驱动需要由受信任 CA 签发的
> 代码签名证书（或通过 WHQL 认证），不能使用本文生成的测试证书。

---

## 一、为什么需要这一套

Windows 从 Vista x64 起强制要求内核驱动必须有有效签名。未通过 WHQL 的自签名驱动
只有两种加载途径：

1. **测试签名模式**（本文采用）：系统接受由“本机信任”的测试证书签名的驱动。
2. 将证书安装到受信任根 + 关闭驱动签名强制（`nointegritychecks`），安全性更差。

测试签名模式是微软为驱动开发者保留的正规途径，也是本文推荐的方式。

---

## 二、准备测试环境（需重启）

### 1. 关闭安全启动（UEFI）

**测试签名模式要求安全启动处于关闭状态**，两者互斥。Windows 会拒绝在安全启动开启时
接受测试签名驱动。

进入 UEFI/BIOS 的方法因主板而异，通常是开机时连按 `Del` / `F2` / `F10` / `F12`。
找到并关闭：

- `Secure Boot` → **Disabled**
- 有的主板叫 `安全启动` / `Boot Mode: UEFI` 需改为 `Legacy`（不推荐，尽量只关安全启动）

保存退出。进入系统后确认：

```powershell
Confirm-SecureBootUEFI    # 期望报错或返回 False 表示已关闭
```

> 若命令报“此平台不支持安全启动”，说明是传统 BIOS 启动，无需此项，直接下一步。

### 2. 开启测试签名

以**管理员身份**打开 PowerShell：

```powershell
bcdedit /set testsigning on
```

### 3. 重启

```powershell
Restart-Computer
```

重启后桌面右下角会出现 **“测试模式”** 水印，这是正常的，表示测试签名已生效。

### 4. 确认状态

```powershell
bcdedit /enum "{current}" | Select-String testsigning
# 期望看到: testsigning             Yes

# 若驱动是 32 位且系统是 64 位，可能还需要：
bcdedit /set nointegritychecks on
```

## 三、生成签名证书（含私钥）

用自己的自签名证书给驱动签名，并把公钥装进本机受信任存储。

### 1. 创建证书

```powershell
# 创建代码签名证书（私钥保存在当前用户的证书存储中）
$cert = New-SelfSignedCertificate `
    -Type CodeSigningCert `
    -Subject "CN=UmSerialFilter Test" `
    -KeyUsage DigitalSignature `
    -KeyAlgorithm RSA `
    -KeyLength 2048 `
    -HashAlgorithm SHA256 `
    -CertStoreLocation Cert:\CurrentUser\My `
    -NotAfter (Get-Date).AddYears(5)

$cert | Format-List Subject, Thumbprint, NotAfter
```

记下输出中的 **Thumbprint**（指纹），后面签名要用。

### 2. 导出为 .pfx（含私钥）

```powershell
$pwd = Read-Host "设置 PFX 密码" -AsSecureString
Export-PfxCertificate -Cert $cert -FilePath driver\umfilter-test.pfx -Password $pwd
```

> ⚠️ **`.pfx` 包含私钥，绝不要提交到版本库**。本仓库的 `.gitignore` 已排除
> `*.pfx` / `*.pvk` / `*.key` / `*.snk`。丢失私钥意味着必须重新生成证书并重签。
> 建议把 `.pfx` 备份到安全位置。

### 3. 导出公钥证书并信任它

```powershell
# 导出公钥部分（不含私钥，可安全分发）
Export-Certificate -Cert $cert -FilePath driver\umfilter-test.cer

# 装入“受信任的根证书颁发机构”——驱动才会被认为是可信链的末端
Import-Certificate -FilePath driver\umfilter-test.cer `
    -CertStoreLocation Cert:\LocalMachine\Root
```

上一步需要管理员权限。装完后可在 `certlm.msc` → 受信任的根证书颁发机构 中看到它。

## 四、签名驱动

### 方式 A：使用仓库脚本（推荐）

`driver/rebuild-all.ps1` 会依次完成：清理残留 → 编译 → 同步 → 签名 → 安装 → 启动。

```powershell
cd MonitorAnything\driver
# 以管理员身份运行
powershell -ExecutionPolicy Bypass -File rebuild-all.ps1
```

脚本会自动定位 `signtool.exe`（取已安装的最新 SDK 版本）。

### 方式 B：手动签名

```powershell
# 找到 signtool（位于 Windows Kits 的 bin 目录）
$signtool = (Get-ChildItem 'C:\Program Files (x86)\Windows Kits\10\bin' -Directory |
    Sort-Object Name -Descending |
    ForEach-Object { Join-Path $_.FullName 'x64\signtool.exe' } |
    Where-Object { Test-Path $_ } | Select-Object -First 1)

$thumb = (Get-ChildItem Cert:\CurrentUser\My |
    Where-Object { $_.Subject -like '*UmSerialFilter Test*' } |
    Select-Object -First 1).Thumbprint

# 签名（证书在“当前用户\个人”存储中）
& $signtool sign /s My /sha1 $thumb /fd SHA256 /v driver\umserialfilter\umserialfilter.sys

# 验证签名
& $signtool verify /pa /v driver\umserialfilter\umserialfilter.sys
```

若签名时提示找不到证书，用 PFX 文件方式：

```powershell
& $signtool sign /f driver\umfilter-test.pfx /p "<你的PFX密码>" /fd SHA256 /v <驱动路径>
```

## 五、安装驱动

### 方式 A：脚本

```powershell
cd MonitorAnything\driver
powershell -ExecutionPolicy Bypass -File install-driver.ps1          # 安装并启动
powershell -ExecutionPolicy Bypass -File install-driver.ps1 -Status  # 查看状态
powershell -ExecutionPolicy Bypass -File install-driver.ps1 -Remove  # 卸载
```

### 方式 B：手动（sc.exe）

```powershell
$sys = (Resolve-Path driver\umserialfilter\umserialfilter.sys).Path

sc.exe create UmSerialFilter type= kernel start= demand binPath= $sys DisplayName= "Universal Serial Monitor Filter"
sc.exe start  UmSerialFilter
sc.exe query  UmSerialFilter     # 期望 STATE = 4 RUNNING
```

> `binPath=` 后面必须有一个空格，这是 `sc.exe` 的历史语法要求。

## 六、验证

```powershell
# 1. 服务在跑
sc.exe query UmSerialFilter

# 2. 程序能打开控制设备并看到端口
cd app
.\target\release\universal_monitor.exe --driver-test 8
```

期望输出包含「已连接驱动」与捕获到的记录。**连续运行两次**，第二次仍能列出相同的
端口数量才算正常（首次是增量，第二次才是总数）。

也可以在 GUI 里：菜单 **监控 → 启用驱动捕获**，状态栏应显示「驱动：捕获中（N 个端口）」。

## 七、升级与卸载

### 升级

驱动文件被加载时无法覆盖，必须先停服务：

```powershell
sc.exe stop UmSerialFilter
# 重新编译并签名，然后
sc.exe start UmSerialFilter
```

若服务卡在 `STOP_PENDING`（还有未完成 IRP），只能重启后重装。

### 卸载

```powershell
sc.exe stop UmSerialFilter
sc.exe delete UmSerialFilter
```

或用脚本：`install-driver.ps1 -Remove`。

### 若卸载不彻底

`driver/emergency-remove-driver.ps1` 会强制清理服务项与残留注册表键。

### 恢复测试模式设置

不再需要驱动时，建议把系统恢复原状：

```powershell
bcdedit /set testsigning off
bcdedit /deletevalue nointegritychecks   # 若曾设置过
Restart-Computer
```

并在 UEFI 中重新开启 Secure Boot，以及在 `certlm.msc` 中删除前面导入的测试证书。

## 八、常见问题

| 现象 | 原因与处理 |
|---|---|
| `sc start` 报 **error 577**（签名无效） | 测试签名没生效：确认已 `bcdedit /set testsigning on` **并重启**，且安全启动已关闭 |
| 报 **error 5**（拒绝访问） | 没用管理员权限运行 |
| 报 **error 1275 / 加载失败** | 驱动签名链不完整：确认公钥证书已装入“受信任的根证书颁发机构” |
| 设备管理器里驱动有黄色感叹号 | 签名不被认可，处理同上 |
| `--driver-test` 显示"附加到 0 个串口" | 不是故障：该命令返回的是**本次新增**数量。连跑两次，第二次用 `IOCTL_UM_GET_STATS` 的 `attached` 看总数 |
| 装完驱动后系统不稳定 | 先 `sc.exe stop` 并 `sc.exe delete`，重启后再分析；驱动以只读方式镜像 IRP，正常不会改变通信内容 |

## 九、给分发者的提醒

- **不要分发本文生成的测试证书和签名**。它只用于本机开发，私钥一旦泄露，
  任何人都能签一个“看起来来自你”的驱动。
- 对外发布二进制时，驱动需要你**自己的**受 CA 信任的证书，且最好走 WHQL 认证，
  否则用户必须自行关闭安全启动才能安装——这不是可接受的产品体验。
- 仓库中不包含任何签名材料：`.gitignore` 排除了 `*.pfx`、`*.cer`（本地测试证书）、
  `*.pvk`、`*.key`、`*.snk`。详见 [SECURITY.md](../SECURITY.md)。
