## 代码结构

```
app/                      主程序（Rust + egui）
  src/                    UI、会话、解码层、注入器、驱动客户端
    text_codec.rs         字节 → 文本的唯一解码入口（UTF-8/GBK/UTF-16LE）
    protocol.rs           Modbus 解析 + 组帧（组帧仅供单元测试）
    session.rs            会话、过滤、速率、存档（.umses）
  hook/                   注入的 hook DLL（独立 crate，x64 + x86 双编译）
  x86_injector/           32 位注入器（独立 crate，防止被主构建覆盖）
  assets/                 编译期嵌入的资源（关于窗口的二维码）
  tests/                  诊断探针源码与 UI 测试（验证用；编译产物不入库）
  verify-fixed.ps1        注入侧全链路验收脚本
  verify-no-steal.ps1     验证监控时端口不被占用
  verify-dual-arch.ps1    双架构产物校验
  build-all.ps1           一键构建全部注入侧产物并校验架构
  check-all.ps1           本地一键门禁（与 CI 同一套断言）

driver/                   内核驱动（C）
  umserialfilter/         驱动源码
  build-driver.ps1        多架构/多 OS 下限构建
  rebuild-all.ps1         清理→编译→签名→安装→启动
  install-driver.ps1      安装/卸载（签名材料不入库，见 ../SECURITY.md）
  verify-driver.ps1       驱动验证

.github/workflows/ci.yml  CI 门禁（格式 / lint / 测试 / 架构 / 文档 / 密钥守卫）
docs/                     本文档目录
```

## 关于技术分析材料

本仓库**只包含可公开的软件工程内容**。

项目开发早期为了解串口监控原理而做的技术分析（含对第三方商业软件的观察记录、
逆向笔记、驱动规格整理等）**不在本仓库内**，单独保存在仓库外的
`technical-analysis/` 目录，供作者本人日后做技术查阅。

这样安排的原因：

- 仓库可以自由开源，不携带任何可能引发版权争议的材料；
- 代码与公开文档只描述**本软件自身的实现**，不引用第三方产品名称、路径或内部结构；
- 需要追溯"当初为什么这样设计"时，作者可以查阅仓库外的分析材料。

> 如果你是从别处获得本仓库的副本并看到指向 `technical-analysis/` 的链接，
> 那是历史文档遗留的引用，该目录不属于本仓库发布内容。
