# 万能串口监控 · Universal Serial Monitor

[![CI](https://github.com/TianCaibailei/SerialMonitor/actions/workflows/ci.yml/badge.svg)](https://github.com/TianCaibailei/SerialMonitor/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Platform](https://img.shields.io/badge/platform-Windows%2010%20%7C%2011-lightgrey.svg)](#快速开始)

一个 Windows 平台的**串口通信监视工具**。它被动观察其他程序与串口设备之间的字节流，
完整记录、解析并支持事后回看——**全程不占用串口**，被监视的程序照常独占使用该端口。

支持 Modbus RTU / ASCII / TCP 解析、Hex 与文本双视图、UTF-8/GBK/UTF-16 编码显示、
会话存档与多格式导出。

> 定位说明：本软件面向**串口**监视。不提供 TCP/UDP 网络抓包能力；通道类型中的
> TCP/UDP 仅用于对接自带网口的串口服务器（把网络当串口传输层用），不是网络嗅探器。

## 它解决什么问题

串口调试的常见困境：**两台程序不能同时打开同一个 COM 口**。

如果你想看某个业务软件到底往串口发了什么，直接去打开该端口会把它挤掉，业务逻辑当场失败；
抓包工具（如串口助手）也只能看到自己收发的数据，看不到别人的。

本软件的思路是在**不取得端口所有权**的前提下旁路观察：

```
业务程序 ──打开/读写──> COM6 ──> 设备
             │
             └── 字节被复制一份 ──> 本软件显示/解析/存档
                                 （端口仍归业务程序独占）
```

这适用于这些场景：

- **现场排障**：客户现场的设备通信异常，需要看业务软件实际发了什么指令。
- **协议逆向**：手上只有软件和设备，要弄清它们之间的报文格式。
- **回归验证**：改完固件后对比新旧通信是否有差异。
- **长时间值守**：自动化跑一整夜，第二天看完整日志与统计。

## 核心特性

### 数据采集

- **被动监听，不占用端口**：被监视的程序保持对串口的独占访问。
- **两种抓取路径**：用户态注入（免管理员）与内核过滤驱动（全系统覆盖），可按环境选择。
- **按端口/进程定向**：只看关心的端口或某个进程的流量，其余忽略。

### 数据呈现

| 视图 | 内容 |
|---|---|
| Table | 主表格：序号 / 时间 / 通道 / 方向 / 功能 / 长度 / Hex / 文本 |
| 终端 | 按时间顺序的收发全文，适合连续日志的阅读 |
| Dump | 字节级十六进制转储，附带解码出的一行文本预览 |
| Line | 接收/发送速率曲线（真实字节数，空闲秒补 0） |
| Modbus | 结构化字段表：ID / 功能码 / 地址 / 数量 / 值 / 校验 / 备注 |

- **显示编码**：UTF-8 / ANSI(GBK) / Unicode(UTF-16LE)，带 BOM 自动识别。
  编码同时作用于显示、查找、内容过滤、复制与导出，中文内容不再显示为 `\xNN`。
- **状态栏**：实时速率、累计字节、行数、协议、当前编码、抓取链路状态。

### Modbus 解析

- RTU / ASCII(字符帧) / TCP(MBAP) 三种封装，自动切帧。
- CRC-16/MODBUS 与 LRC 校验，逐帧标记通过/失败。
- 请求/响应配对、异常码识别、功能码过滤。
- 内置请求与响应样本库，可用于验证解析器。

### 检索与导出

- **查找**：匹配 Hex，也匹配按当前编码解码后的文本（中文可搜）。
- **过滤**：按方向、功能码、端口、内容组合过滤。
- **导出会话**（`.umses`）：可重新打开的存档，装载后只读回看、不占用端口。
- **导出日志**：文本 + Hex 双列，可选文件编码。
- **导出项目信息**（JSON）：通道配置、协议、编码、统计与过滤条件，便于复现环境。
- **复制为 CSV**：按当前过滤条件导出全部可见行，可直接粘进表格软件。

## 两种抓取方式

| | 注入模式 | 驱动模式 |
|---|---|---|
| 原理 | 向目标进程注入钩子 DLL，拦截其串口 I/O | 内核过滤驱动挂到串口设备栈，镜像 IRP |
| 覆盖范围 | 仅被注入的进程 | 全系统所有进程 |
| 权限要求 | 与被监视进程相同即可 | 管理员 + 测试签名 |
| 部署成本 | 每次注入 | 装一次即可 |
| 是否占用端口 | **否** | **否** |
| 风险 | DLL 缺陷可能影响目标进程 | 驱动缺陷可能导致蓝屏 |

**如何选择**：

- 只是想看看某个软件在干什么 → 用**注入模式**，零配置，点几下就好。
- 需要覆盖多个程序、或不方便逐个注入（服务、开机自启的程序）→ 用**驱动模式**。

建议先用注入模式验证需求，确认长期需要后再装驱动。

## 快速开始

### 1. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（x64） |
| 使用 | 无需额外运行时，程序为静态编译 |
| 编译 | Rust 1.75+（开发使用 1.99），Visual Studio C++ 生成工具 |
| 驱动（可选） | WDK、管理员权限、测试签名环境 |

### 2. 获取与编译

```powershell
git clone https://github.com/TianCaibailei/SerialMonitor.git MonitorAnything
cd MonitorAnything\app
cargo build --release
```

产物位于 `app\target\release\`：

| 文件 | 说明 |
|---|---|
| `universal_monitor.exe` | 主程序（x64） |
| `monitor_hook.dll` | 注入用的钩子（x64） |

32 位目标还需要 `monitor_hook_x86.dll` 与 `universal_injector_x86.exe`，用一键脚本构建（见下）。

### 3. 一键构建全部产物

```powershell
cd MonitorAnything\app
powershell -ExecutionPolicy Bypass -File build-all.ps1
```

该脚本会交叉编译 32 位产物，并**读取 PE 头校验架构**：32 位 DLL 被 64 位构建覆盖时
会直接报错，而不是留下一个“看起来构建成功”的错误产物。

### 4. 自检

```powershell
cd MonitorAnything
powershell -ExecutionPolicy Bypass -File app\check-all.ps1
```

依次检查格式、静态分析、单元测试、双架构构建与仓库卫生。CI 使用同一套断言。

## 编译

### 主程序（Rust）

```powershell
cd app
cargo build --release
```

### 内核驱动（C，可选）

驱动需要 WDK。本项目采用 **NuGet 包 + 独立编译脚本**的路线，不需要完整安装 WDK MSI
或 Visual Studio 集成。详见 [docs/WDK-NUGET-GUIDE.md](docs/WDK-NUGET-GUIDE.md)。

```powershell
cd driver
powershell -ExecutionPolicy Bypass -File build-driver.ps1              # x64 + x86
powershell -ExecutionPolicy Bypass -File build-driver.ps1 -Arch x64    # 只编一个架构
```

支持 Windows 7 至 11 作为编译目标下限（`-Os win7` / `-Os win10`）。

安装、签名与测试签名环境的完整步骤见 [docs/安装与签名指南.md](docs/安装与签名指南.md)。

## 使用

### 观察一个正在使用串口的程序

1. 启动 `universal_monitor.exe`。
2. 菜单 **文件 → 新建监控会话**。
3. 通道类型选 **串口监听(不占用)**，勾选要观察的端口（可多选）。
4. 点确定。此时会话已建立，但还没有数据——因为还没有注入。
5. 菜单 **监控 → 附加到进程(拦截)…**，在列表里找到那个使用串口的程序，双击或选中后点「注入并监控」。
6. 该程序的串口读写开始出现在视图里。

> 附加对话框支持按名称/PID 过滤，并默认隐藏系统服务类进程。

### 使用驱动模式（全系统）

1. 按 [docs/安装与签名指南.md](docs/安装与签名指南.md) 编译、签名并安装驱动。
2. 菜单 **监控 → 启用驱动捕获**。
3. 状态栏显示「驱动：捕获中（N 个端口）」即生效，无需再附加进程。

### 只看关心的端口

菜单 **监控 → 过滤设置**，在「监视端口」里勾选需要显示的端口。
未勾选的端口连数据行都不会产生（不是仅仅隐藏）。两条抓取路径共用这份白名单。

### 中文内容显示为乱码

菜单 **设置 → 显示编码**，按设备实际编码选择 UTF-8 / ANSI(GBK) / UTF-16LE。
切换后对所有视图、查找、过滤、复制与导出同时生效。当前编码常驻状态栏。

### 回看历史

- 菜单 **文件 → 保存会话**，选择保存位置（`.umses` 格式）。
- 之后 **文件 → 打开会话** 选择该文件即可回看，装载的会话是只读的、不占用任何端口。

### 导出给同事

- **导出日志**：人可读的文本 + Hex。
- **导出项目信息**：JSON，含通道配置与统计，便于对方复现环境。
- **复制全部为 CSV**：直接粘进 Excel 做分析。

## 命令行工具

程序同时提供若干诊断子命令，用于在没有界面的环境下验证链路（均需在 `target\release\` 下运行）：

| 命令 | 用途 |
|---|---|
| `--list-procs` | 列出可注入的进程 |
| `--holders COM6` | 查看谁在持有该端口 |
| `--find-owners COM6` | 端口持有者详细诊断 |
| `--inject-test <pid>` | 注入并验证模块是否加载成功 |
| `--hook-e2e COM6 COM7` | 钩子 → 管道 → 会话全链路自测 |
| `--driver-test <秒>` | 驱动连通性与捕获测试 |
| `--driver-latency <秒>` | 测量驱动记录的到达延迟 |
| `--headless-watch COM6 --result out.json` | 无界面运行并输出统计 |
| `--screenshot <file.png>` | 渲染界面截图后退出 |

## 已知限制

- **仅支持 Windows**。依赖 Windows 的 IAT/内联挂钩与内核过滤驱动。
- **注入模式只能看到注入之后的调用**。如果目标程序在注入前已经打开了端口，
  本软件会主动识别该句柄（通过串口专属 IOCTL 判定），因此仍能捕获，但极早期
  的初始化数据可能漏掉——这也是驱动模式存在的意义。
- **驱动模式需要测试签名环境**，不能用生产签名证书直接装未通过 WHQL 的驱动。
- **TCP/UDP 通道不是网络抓包**，仅作为串口传输层的替代通道使用。
- **单会话行数上限 100 万行**，超出后按批丢弃最旧数据并重置选择与查找位置。
